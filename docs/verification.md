默认28项：

- 业务模型5项：规则快照、十五天期限、逾期边界、归还幂等、额度及合法值。
- 数据迁移1项：十五书四账号、初始计数、无数据库外键、关联字段注释、主键持续生成、文件重新连接及迁移不覆盖数据。
- 锁协调3项：顺序、第二把锁失败释放第一把、解锁异常不覆盖成功或业务拒绝。
- 事务边界2项：执行失败回滚、提交阶段失败报告结果未知。
- 应用集成17项：API、归属、分页、规则修改、各阶段回滚、逻辑关联匹配、无锁重叠执行保护、旧规则在途请求等。

真实组件6项运行两个独立 Spring HTTP 应用实例，各有自己的连接池和 Redisson 客户端，连接同一个数据库与 Redis：

1. MySQL迁移、字段注释、无外键约束及跨实例读取。
2. 最后一个图书名额竞争。
3. 同账号九本时并发借两本不同书。
4. 跨实例并发归还，返回时间一致且额度只释放一次。
5. 用真实 Redis 删除已经持有的账号锁，使两个请求进入数据库竞争；最终最多一笔成功，数量一致。该场景也实际触发并验证了丢失锁后释放异常不覆盖已提交结果。
6. 锁客户端失效后读取可用、写入503；新应用指向不可用 Redis 端点仍能启动，读取与 readiness 可用。

外部集成测试模式不停止调用方提供的 Redis，所以第6项使用应用锁客户端失效和实际不可用端点。额外的打包JAR验收则实际停止、重启了本任务自建的专用 Redis8.4.0，验证真实服务停止与恢复。Docker容器分支仍未执行。

每个集成场景之后检查：账号计数与当前关系一致，图书占用与当前关系一致，借阅归还状态与当前关系一致，逻辑关联存在且匹配。
